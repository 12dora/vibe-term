# Hub/Node Docker 实测 Harness

## 背景

把「一台公网 hub + 两台 NAT 后 node」的 mesh 装进 Docker，用脚本走完 enroll / join / 登录 / 终端 / 文件 / hub 宕机恢复，而不是只靠进程内 integration test。不调用 `tmex init`（容器里没有 systemd/launchd），按安装布局手铺 `/opt/tmex`。

本 harness 只新增 `scripts/hub-e2e/`，不改应用源码。容器内 tmux 使用独立 socket（`tmex-hub` / `tmex-node-a` / `tmex-node-b`），不会碰到宿主机名为 `tmex` 的 session，也不会写本机生产安装目录。

## 拓扑

```
                     127.0.0.1:18443
                            |
                         [caddy]
                   TLS: hub.tmex.test
                        entry.tmex.test
                     /        |        \
               edge /    uplink-a    uplink-b
                   /          |          \
               [hub] ---- [node-a]     [node-b]
            hub,node        node          node
                              \            /
                               \   lan    /
                          (默认不连，场景 4 再 connect)
```

- `edge`：caddy、hub、node-a。浏览器/驱动走 HTTPS。
- `uplink-a`：hub 与 node-a。
- `uplink-b`：caddy 与 node-b。**hub 不加入 uplink-b**，避免与 node-b 共网把 peer:39001 判成 `lan`，场景 3 才能稳定看到 `reach=relay`。
- `lan`：仅 node-a ↔ node-b，脚本运行时 `docker network connect/disconnect`。
- 驱动跑在 `driver` 容器（同一 `tmex-e2e` 镜像，挂仓库，`NODE_EXTRA_CA_CERTS=/ca/ca.crt`）。TLS 用 harness 生成的私有 CA；Bun 1.3.14 的 `fetch`/`WebSocket` 都认该变量。不改宿主机 `/etc/hosts`。

镜像策略：上游只留 `ubuntu:24.04` 与 `caddy:2`。Bun 1.3.14、Node 22、tmux、rsync、openssl、curl、tmex tarball 全部打进 `tmex-e2e`。目标平台 `linux/amd64`。

## 本地运行

预构建包（本 worktree `bun run build && (cd packages/app && npm pack)`）：

```bash
TMEX_TARBALL=/path/to/tmex-cli-1.0.2.tgz scripts/hub-e2e/run.sh
```

结束：

```bash
scripts/hub-e2e/run.sh down    # compose down -v
```

可选环境变量：`TMEX_E2E_USER`（默认 `alice`）、`TMEX_E2E_PASSWORD`。

产物在 `scripts/hub-e2e/out/`（gitignored）：`report.md`、各容器日志、cookie、enroll 日志。

保存镜像供离线机：

```bash
docker save tmex-e2e:latest caddy:2 -o tmex-e2e-images.tar
```

## 远端（无 Docker Hub）运行

1. 把 `tmex-e2e-images.tar`、本仓库（至少 `scripts/hub-e2e/` + 驱动依赖的 workspace 包 / `node_modules`）拷到目标机。
2. `docker load -i tmex-e2e-images.tar`
3. `scripts/hub-e2e/run.sh --image-tar /dev/null` 仍会 `docker build`；已 load 时可直接：

```bash
# 镜像已在本地后，跳过 build：把 run.sh 里 IMAGE_TAR 指到已 load 的任意 tar，
# 或先 docker load，再：
TMEX_TARBALL=/path/to/tmex-cli-1.0.2.tgz scripts/hub-e2e/run.sh --image-tar tmex-e2e-images.tar
```

`--image-tar` 走 `docker load`，不再访问网络拉 Bun/Node。Caddy 用已 load 的 `caddy:2`。仍要在目标机生成 CA（`gen-ca.sh`，只需 openssl）。

## 场景断言

| # | 断言 |
|---|---|
| 1 | hub `/healthz`；`hub user add`；`/api/auth/mode` 含 `rootEpoch` / `rootPublicKey` / `hubPublicUrl` |
| 2 | node-a、node-b join 成功；`/api/hub/nodes` 两者 `online:true` |
| 3 | hub 入口登录；mesh 列表含两 node；登录 node-b；在 node-b 建 local device + tmux；marker 回环；此时 `lan` 未连，`reach=relay` |
| 4 | `docker network connect` lan；60s 内从 node-a 看 node-b `reach=lan`；marker 仍通 |
| 5 | node-b `/e2e/marker.txt`；经 `/n/<id>/api/files/*` list + content |
| 6 | node-a 为入口且 lan 仍在，`docker stop hub`；既有 cookie 下终端 marker 与文件列表仍通；`/api/mesh/nodes` 仍列出 node-b |
| 7 | `docker start hub`；90s 内 `/api/hub/nodes` 两者 online；旧 cookie 无需重登 |
| 8 | 在 node-a 用 **Bun** 跑 `direct enable`；有 `native/node_datachannel.node` + `manifest.json` 且 `direct_capable=true` 则 PASS，npm 拉包失败则 SKIP，不判 FAIL |

`hub join` 在无服务管理器的容器里会在写完 `app.env` 后因 restart 非零退出。脚本在 **停止 node 进程后** join，只要 `app.env` 已有 `TMEX_HUB_URL` 与 `TMEX_ROLES=node` 即视为成功，然后 start。Token 不重试。

Enrollment 只在 hub 上跑（非 hub `enroll` 期望 login JSON 里有 `sid`，与网关实际返回不一致）。

## 已知限制

- 不覆盖 RTC 直连中断回落、passkey、TOTP、浏览器 Playwright。
- `reach=lan` 含直连 WS 与 RTC，不能证明已经走 DataChannel。
- 场景 8 依赖容器内访问 npm registry；离线机预期 SKIP。
- 私有 CA，不是 Let’s Encrypt；只适合封闭实测。
- 不测 macOS NAT node、IPv6 ICE、文件 bulk 直连。
- 认证 CLI 在容器里请用 `bun /opt/tmex/runtime/cli-auth.js`：`node dist/cli-node.js` spawn bun 后 stdout 被吞，enroll token 读不到。
- `hub join` 的 `writeEnvFile` 对 symlink 做 `rename`，会把 `/opt/tmex/app.env` 变成 overlay 普通文件；harness 在 join 后把文件拷回 volume。
- **产品缺口（场景 4/6）**：非 hub 的 node-a 在 `GET /api/mesh/nodes` 里看不到后加入的 node-b（只有 self + hub 证书行），`mode.hubNodeId` 为 null，经 node-a 转发 `/n/<node-b>/*` 返回 `NODE_UNREACHABLE`。hub 作 entry 则 relay 正常。根因假设：uplink `node.list` 没有把其它 node 的证书写入该机 `userStore`（`mesh-routes.ts` `collectNodes` 只枚举 `listCerts()`）。

驱动跑在 `driver` 容器（同一 `tmex-e2e` 镜像，挂仓库，`NODE_EXTRA_CA_CERTS=/ca/ca.crt`）。不改宿主机 `/etc/hosts`。curl 走 `--cacert`（curl 不认 `NODE_EXTRA_CA_CERTS`）。
