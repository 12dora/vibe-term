# TUI 主题热切换：mode 2031 通知注入

## 背景

tmex 前端切换亮/暗主题后，此前只有"其后新启动"的 TUI 能拿到正确亮暗（tmux 以 window-style 的 bg 代答 OSC 10/11 查询）；正在运行的 TUI 不跟随。本功能让 gateway 在主题切换时对订阅了 DEC private mode 2031 的 pane 注入标准主题通知，实现运行中热切换。可行性与各方行为经全量实测（`prompt-archives/2026070500-tui-theme-auto-switch/research-02-live-behavior-matrix.md`）。

## 机制

```
pane 输出（%output，字节保真）
  → pane-stream-parser 新增 CSI 收集态：旁路识别 CSI ?2031h/l（原样回填输出流，
    多参数形态如 ?1004;2031h 也识别；DCS tmux passthrough 解包内容不计入）
  → connection（local/ssh 对称）ThemeSubscriptionTracker：
      内存 Set + tmux pane 用户选项 @tmex_2031 持久化（gateway 重启后 list-panes 恢复）
      清位：?2031l / OSC 133;A 提示符标记（前台回到 shell）/ pane 消失 / 连接销毁
  → 主题切换编排（ws 层 scheduleTmuxThemeApply，latest-wins 合并快速连切）：
      1. await 全设备 window-style 更新落地（保证 TUI 重查 OSC 11 拿到新色）
      2. 对订阅 pane 注入 CSI ?997;{1|2}n（1=dark，2=light），走 send-keys -H 输入链
```

时序是硬约束：先 window-style 后 997。反例实测：顺序颠倒时 opencode 收到通知重查拿回旧背景色，会"正确地拒绝"切换。

## 行为分档（2026-07-05 版本快照）

| TUI | 行为 |
|---|---|
| Claude Code（theme=`auto`） | 收 997 即时换肤；theme 固定值时收 997 无操作、无副作用 |
| opencode | 收 997 → 重查 OSC 10/11（tmux window-style 代答）→ 按亮度选 dark/light 变体换肤 |
| oh-my-pi (omp) | 同 opencode（`theme.dark`/`theme.light` 双槽位自动二选一） |
| codex | 不支持 mode 2031，运行中不跟随；**重启后**经 OSC 11 代答拿到正确亮暗 |

tmux 版本无分支：3.0+ 一套代码。3.6+ 上 tmux 自身也会因 window-style 变化向订阅 pane 发原生 997（同值双发），TUI 幂等（实测重复通知不重绘）。

## 配置

- `TMEX_THEME_NOTIFY_2031`：kill switch，默认 `true`；置 `0`/`false`/`no` 关闭注入（订阅跟踪照常，仅不发通知）。

## 已知限制

- **codex 需重启生效**（上游无热切换通道，focus 注入实测无效已放弃）。
- **挂起残留**：TUI 被 Ctrl-Z 挂起不发 `?2031l`（实测 opencode），若 shell 无 OSC 133 集成（prompt-marker 清位失效）且此时切主题，997 字面量会一次性泄漏到 shell 命令行；有 shell 集成时提示符出现即自动清位。
- gateway 停机期间新启动的 TUI 订阅无从得知（%output 已过），表现为静默降级（主题切换对它无效，重启 TUI 恢复）。
- 订阅状态恢复依赖 `@tmex_2031` pane 选项，若停机期间 TUI 退出而 pane 复用（新 shell），恢复后的首次注入可能泄漏一行——prompt-marker 出现即自愈。
