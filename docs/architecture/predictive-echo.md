# 终端预测回显

本文说明浏览器终端的预测回显（mosh 式本地回显）：何时启用、预测与对账规则、绘制方式与安全边界；面向改动 `packages/terminal-ui/src/prediction/` 与 `packages/ghostty-terminal` 预测层的开发者。

## 背景与目标

远端 pane 的按键要经过浏览器 → 节点链路 → tmux → 回显，跨境链路 RTT 常在 100 ms 以上且有抖动，打字明显发粘。预测回显在本地先画出按键的预期结果，服务器回显到达后再对账；预测错了立即撤掉。目标是让常见的 shell 输入「感觉零延迟」，同时保证预测内容永远不进入终端网格、不发往服务器。

## 启用条件

- 设置「终端 → 预测回显」：自动（默认）/ 开启 / 关闭，存在浏览器本地（`useUIStore.predictiveEcho`）。
- 自动模式按该 pane 所属节点的链路 RTT 判定：≥ 50 ms 开启，< 30 ms 关闭（滞回）。RTT 取浏览器直连的 ICE RTT，否则取传输心跳延迟。本机 pane 通常低于阈值，不会开启。
- 未激活时只有激活判定在入口包里；引擎与控制器在激活时才 `import()`，不订阅帧、不创建预测画布与字宽探针。
- 以下状态不预测并清空已有预测：备用屏（DECSET 47/1047/1049）、密码输入、光标隐藏、鼠标上报、同步输出（2026）、视口不在底部、编辑器模式、IME 组字中。

## 预测规则

- 只预测行尾追加的可打印字素（宽字符按终端内核的字宽规则占 2 列）和退格；不跨右边界换行。
- 回车、控制字符、转义序列（含方向键）、粘贴结束当前 epoch。新 epoch 的预测先「暂定」不显示，直到其中一个非空白预测在光标所在行被服务器确认，之后同 epoch 的预测立即显示。这样可避免向不回显的程序（如未标记的密码提示）画出输入。
- 已显示的 epoch 允许覆盖非空白格（fish / zsh 自动建议的灰字）；暂定 epoch 遇到非空白格只跳过该键，不中断 epoch。
- 快捷键条发送的按键、粘贴经 `notePaneInput` 通知引擎，与键盘输入同样处理。

## 对账

- 预测按绝对行（`viewportTop + row`）记录。格子内容相同且真实光标已越过该格即确认；确认后从叠层移除。
- 光标已越过但内容不同即误判；光标跳到别处先记「可疑」，要后续帧佐证且超过 120 ms 宽限才算误判；只有单帧可疑时静默清除，不计数（输出突发中的中途光标位置不误杀预测）。
- 超过 max(1500 ms, 4 × RTT) 仍未确认视为过期。滚出视口的预测静默丢弃。
- 误判清空全部预测并开始新的暂定 epoch；30 s 内 3 次用户可见的误判则暂停预测 60 s。
- 快照替换、历史页、reset、resize（generation 变化）、重连都清空预测。

## 绘制

`packages/ghostty-terminal` 通过 `CompatibleTerminalLike.prediction`（`TerminalPredictionHost`）提供：

- `onFrame` / `frame()`：每次渲染完成后的光标、模式、视口与按需读取的格子内容；
- `setOverlay`：在独立的 `prediction` 画布层（主层与链接层之上、选区层与光标层之下，首次使用时创建）绘制预测格：默认背景填充 + 默认前景字形，未确认的带下划线；可同时把光标画在预测位置；
- `textWidth`：用私有探针终端按内核规则计算字素列宽。

叠层只画在独立画布上，从不调用 `write()` 写入内核网格。

## 已知限制

- 预测格使用主题默认背景，在带 SGR 背景色的输入栏里确认前会显示为默认背景色块。
- 心跳 RTT 约 5 s 更新一次，自动模式对瞬时抖动不敏感。
